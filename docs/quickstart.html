evo.videostroll

MCP server + Claude Code skill
quickstart · setup · voices · evomedia.net

An agent records a narrated walkthrough of a website. It drives the browser, a visible cursor follows, the narration is spoken aloud, and captions come out with timestamps.

See it first

This is the tool's own output — a walkthrough of the three pages you are looking at, recorded, narrated and captioned in one pass. Twelve steps, seven chapters, a minute and three quarters. Nothing was edited afterwards, and the captions below are the file it wrote, burned in.

The storyboard that produced it is beside it: videostroll-demo.storyboard.json. That file is the point — when this site changes, the steps that changed get edited and it renders again, rather than being recorded a second time.

1 What you need

Node.js, version 20 or newer. Node is the program that runs JavaScript outside a browser — this tool is written for it, and it is not something Windows or macOS comes with. If you have never installed it, get the LTS build from nodejs.org and accept every default.

To find out whether you already have it, and which version, open a terminal:

node --version   # v20.x.x or higher — any lower and the install will fail

If that prints v18 or says the command is not found, install from the link above before going on. Nothing else is required: the video encoder ships inside the package, so there is no separate ffmpeg to install. The default voice is a network call; an offline voice is available if you would rather not make one.

2 Install and build

Clone the repository, then install from inside server/. The browser download is a one-off.

# from the folder where you keep your projects
git clone https://github.com/evomedia-net/evo.videostroll
cd evo.videostroll/server

npm ci
npx playwright install chromium
npm run build

Confirm it works before wiring anything up. Every test runs offline.

npm test        # the whole suite, no network

Prefer not to clone? The package installs from npm and carries the skill with it — see step 4.

Would rather fill in a form than read ten steps? The setup page asks plain questions — which site, what size, which voice, where the files go — and gives you a sentence to paste. It needs this install done first, and nothing else.

3 Register the server

This step needs Claude Code, Anthropic’s command-line tool — the claude command below is part of it, not part of this project. If you do not have it, install it first from claude.com/claude-code, which covers Windows, macOS and Linux. Check it is there:

claude --version

Then point it at the built server. One command registers it for every project on the machine. Use the path form your shell expects — the only difference is the slashes and the line continuation.

Windows · PowerShell

claude mcp add -s user videostroll -- `
  node C:\path\to\evo.videostroll\server\dist\index.js

macOS · Linux · Git Bash · WSL

claude mcp add -s user videostroll -- \
  node /path/to/evo.videostroll/server/dist/index.js

Replace the path with wherever you cloned it. Then check it took — you are looking for the word Connected.

claude mcp get videostroll

Any other MCP client works too: point it at node …/server/dist/index.js, or at npx evo.videostroll.

4 Install the skill

The server records. The skill is what makes the recording worth watching: it tells the agent to read the product’s own documentation, read the page, storyboard before recording, keep narration to two sentences, and verify the result. Copy it out of the repository.

mkdir -p ~/.claude/skills/videostroll
cp skill/SKILL.md ~/.claude/skills/videostroll/SKILL.md

Edit it in the repository and copy it out again. Never the other way round.

If you installed from npm rather than cloning, the skill ships inside the package and one command puts it in the same place:

npx evo.videostroll --install-skill
npx playwright install chromium   # the recorder still needs a browser

5 Keeping this machine current

There is no server to deploy to, but “installed” is three separate things, and git pull is only the first of them:

  • 1. The source — what git pull brings down.
  • 2. The built server — server/dist/, which is gitignored and is what your MCP client actually runs. A pull alone leaves it on stale compiled code, so the new source is on disk and none of it is running.
  • 3. The installed skill — the copy at ~/.claude/skills/videostroll/SKILL.md. It is a copy, so nothing notices when it falls behind the one in the repository.

One command does all three and tells you which of them moved.

npm run deploy:local              # pull, rebuild, copy the skill, report
npm run deploy:local -- --check   # what is stale, change nothing

It refuses to pull over uncommitted changes or onto a branch that is not the default, and says so rather than reporting everything as current.

6 Ask for a walkthrough

That is the whole setup. Start a session and ask in plain words.

“Record a two minute walkthrough of https://example.com
 for someone who has never seen it.”

The agent reads the page, drafts the steps, records them one at a time, and checks what it recorded against what it said.

7 It reads the product’s docs first

Before writing a word of narration, the agent looks for the site’s own documentation. Narration that uses a product’s own nouns sounds like someone who works there; narration that invents its own sounds like a stranger reading labels off the screen — and the page itself shows what is there, never what any of it is called.

It looks where a person would: llms.txt first, then /docs, docs.<site>, /help, /guide, and finally any link on the page that reads like a way in. What comes back is vocabulary, not pages:

  • glossary — what the product calls its features, one line each.
  • tasks — its procedures, found by title and by spotting a numbered list, which is how it finds them on the many sites whose headings are all nouns.
  • pronunciation — how to say the awkward names aloud. It reads the docs to decide, so it knows “evo dot e h s” from “evo dot orchard”.

Nothing is needed from you — the skill does this on its own. A site with no documentation is an ordinary outcome, not an error; the agent falls back to the wording in the interface.

This site publishes one, so you can read exactly what a scan of it sees: llms.txt.

What comes back is treated as data, never as instructions. It is text written by whoever runs the site, and it ends up spoken aloud in a video you publish. Lines that look like an attempt to redirect the agent are dropped and counted rather than quietly swallowed. That is a speed bump, not a wall — watch a walkthrough of a site you do not control before you publish it.

How to use it

Normally you do nothing. The skill does this on its own the moment you ask for a walkthrough — there is no setting to turn on and nothing to install.

You only need to say something when the automatic search would get it wrong. You are talking to the agent, in the chat, in the same message where you ask for the walkthrough — there is no flag and no config file for this:

“Record a walkthrough of https://app.example.com.
 The documentation is at https://example.com/handbook.”

To skip it entirely — a site with no docs worth reading, or one you would rather it did not fetch — say so the same way:

“Record a walkthrough of https://example.com.
 Don’t read the site’s documentation.”

If writing that sentence is the part you would rather not do, the setup page builds it for you from a form.

8 Sites behind a login

The recorder never types a password and a storyboard never holds one. You sign in yourself, once, and it keeps the session.

npm run login -- https://app.example.com

A real browser window opens. Sign in however the site asks — password manager, second factor, SSO — then press Enter in the terminal. The session is written to auth/<host>.storage-state.json, which git ignores, and a storyboard points at it.

{ "url": "https://app.example.com/dashboard",
  "storageState": "auth/app.example.com.storage-state.json" }

That file is a live session — treat it like a password. Sessions expire, so check one before you rely on it.

npm run login -- --check auth/app.example.com.storage-state.json

This is the one step that needs a full browser. Recording is headless and uses a different build, so a machine can record for weeks and still fail here. It opens the Chrome or Edge you already have; --browser chromium forces Playwright’s own. Every run leaves a log in auth/.

9 Or render a storyboard

Every recording also writes the storyboard that produced it. When the site changes, edit the steps that changed and render again. No agent needed.

npm run render -- ../examples/storyboards/example-com.json out/

Writing one from scratch is easier from the setup page: it produces the settings, and you add the steps.

10 What comes out

walkthrough.mp4H.264 and AAC, 30fps, 1080p by default
walkthrough.captioned.mp4the same, captions burned in
walkthrough.srt / .vttcaptions aligned to the spoken words
walkthrough.jsonsteps, cues, chapters, durations
walkthrough.storyboard.jsonre-render it, do not redo it
thumbs/one still per step, named like walkthrough-01-intro.jpg

walkthrough is just the default name. Set name and every file above follows it — "name": "onboarding" gives onboarding.mp4, onboarding.srt and the rest, which is what stops a second recording overwriting the first. A file name only: a slash or a leading dot is refused, because the value is joined onto the output folder.

1080p is the default, not the only size. The recording is the browser viewport, so setting the viewport sets the resolution — anything from 320×240 upwards.

{ "viewport": { "width": 1280, "height": 720, "deviceScaleFactor": 2 } }

deviceScaleFactor is the pixel density, 1 to 3. At 2 a 1280×720 viewport records 2560×1440 — a retina-sharp frame of a layout that is still laid out for 1280, which is usually what you want rather than a 4K viewport full of tiny text. It costs encode time and file size in proportion.

Odd numbers are safe: H.264 needs even dimensions and the encoder rounds down for you. A phone-shaped walkthrough is just a narrow viewport — 390×844 records like a handset, though the site is responsible for responding to it.

11 Voices

Pick one rather than guessing a name. The default provider offers 322 voices — 47 of them English, split almost evenly between male and female — each listed with its gender and character.

npm run voices -- en-US female

Or open the picker and hear them: filter by locale, gender or character, play a sample at the rate you want, and copy the line straight into a storyboard. A single step can name its own voice, so one walkthrough can hand off between narrators.

  • edge — the default. A network call, word-level timings, nothing to install.
  • piper — fully offline. Set PIPER_PATH and PIPER_MODEL.
  • silent — real timings, no audio. What the test suite uses.

No provider quietly falls back to another. If the one you asked for cannot speak, the run stops and says so.
